Protocol Description (v8)

Quick Crypt implements the protocols below to encrypt, validate, and decrypt data. This information is provided to help you understand how Quick Crypt works and allow you to assess its strength and trustworthiness. If you believe the protocols can be improved, please file a ticket. Also see:

  • Searchable pdf protocol notation
  • Cipher flow diagrams

Quick Crypt uses WebAuthn ( Passkeys ) to create and authenticate user identities. Since this is a standard protocol described in detail elsewhere, including the Mozilla developer network , WebAuthn is described only at a high level to illustrate how user IDs and credentials are created and retrieved for cryptographic functions.

Cipher Data Structure

The table below illustrates the byte-level structure of cipher data created by Quick Crypt's version 8 protocol. When output to the browser UI, this data is base64url encoded and displayed as JSON or a URL. When saved to a file, the binary structure is streamed directly to the file. The subscript values below indicate which fields are used to generate and validate the MAC tags.

To be compatible with version 1 data, the starting fixed length 256-bit MAC was preserved. If future versions create larger MACs, they may need to be split across the header and payload sections to keep the header length consistent across versions.

Protocol v8 Changes

Cipher key hash added to stored associated data to provide full key commitment for all cipher modes
Length prefixes added to key derivation material to make encoding unambiguous
Extra key material removed from associated data and used only for key derivation
Loop number, protocol version, algorithm ID, and extra key material added to block cipher key derivation for domain isolation
Password hints padded to a 16 byte modulus before encryption to obscure hint length
